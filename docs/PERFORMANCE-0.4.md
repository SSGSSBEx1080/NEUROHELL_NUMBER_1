# Измерения редакторского процесса 0.4

Замер 2026-10-18, код приложения `56944ec1699e6f4485125060362af425ce98852d`. Это проверка конкретной нагрузки, **не сравнение с Photoshop, не Windows benchmark и не заявление «вдвое быстрее»**.

## Условия

- Linux sandbox, Intel Xeon @ 2.60 GHz; Chromium 153.0.8010.0, headless, `--disable-gpu`.
- Production bundle, окно 1536×960.
- Учебная страница 896×1200; после J пять слоёв. Для nudge меняется положение верхнего связанного текста; кеши прогреты.
- Используется созданная для проекта иллюстрация, не реальный скан.

## Результаты одного прогона

| Проверка                                              | Значение                                                            | Что измерено                                                                                                                  |
| ----------------------------------------------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| J, гладкий фон, 24 990 целевых пикселей, 5 workers    | 96.6 / 88.6 / 87.4 / 97.6 / 96.5 мс                                 | От postMessage до result; включает передачу/оставшийся startup, не включает захват/копирование источника и UI debounce 140 мс |
| 30 перемещений текстовой рамки, HUD p50 / p95 / max   | 0.2 / 0.5 / 0.9 мс                                                  | CPU-время submit отрисовки Canvas 2D; не input latency, не завершение GPU и не FPS                                            |
| Два крайних положения ползунка J, ROI 300×200         | 0 записанных RGBA-пикселей через putImageData                       | E2E-инструментирование подтверждает кеш/clip вместо полной перекраски массива                                                 |
| Интерполированный штрих запрета доноров на той же ROI | менее 30 000 записанных RGBA-пикселей при 60 000 пикселей фрагмента | E2E проверяет локальный dirty rectangle до запуска следующего worker; это не коэффициент ускорения всей операции              |

Метрики зависят от CPU, устройства, шрифта, масштаба, слоёв и их эффектов. Texture/exemplar на сложной странице существенно тяжелее smooth-case. Предел ROI/целевых пикселей и 60-секундное завершение worker — защита интерфейса, не гарантия результата.

## Воспроизвести

На Linux с установленными npm-зависимостями, в двух терминалах:

```bash
npm run build
npm run preview -- --host 0.0.0.0 --port 4173 --strictPort
# второй терминал, тот же репозиторий:
node scripts/benchmark-layout.mjs
```

Скрипт использует реальный production UI, пять раз обводит область, применяет последнюю, размещает перевод и двигает его 30 раз. Пишет условия/результат в игнорируемый `test-results/performance-0.4.json`; исходники не меняет. Перед сравнением код/сборка/оборудование должны совпадать. Сам preview server нужно остановить перед `npm run test:e2e`, поскольку тесты поднимают свой сервер на том же порту.

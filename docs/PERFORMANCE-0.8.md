# Оптимизация 0.8 — замеры и план

Рабочий журнал оптимизации поверх завершённого функционала 0.8. Каждое изменение
принимается только с замером «до/после» и без изменения поведения (unit/e2e зелёные).
Замеры: production build, Linux-песочница, gzip -c для размеров.

## Намеченные шаги

1. **Горячий путь градиентов**: кеш скомпилированных точек прозрачности, убрать
   аллокации массивов на каждый семпл шума/градиента и лишнюю копию канваса
   у внешних обводок в `renderStyled`. Поведение и пиксели не меняются.
2. **Code-splitting диалогов**: тяжёлые модальные окна (стили, градиенты, пакет,
   шрифты, фильтры и т.д.) вынести из первичного чанка в lazy-чанки. Редактор,
   панели и холст остаются синхронными.
3. **Мемоизация предпросмотра градиента** в опциях инструмента и редакторе,
   чтобы перерисовки App не пересчитывали семплы без изменения данных.
4. Повторный замер, полная регрессия локально + Windows CI.

## Результаты

### Шаг 1 — горячий путь градиентов (коммит 2480457)

Парный микробенчмарк в одном процессе Node (старая версия из HEAD vs новая,
по два прогона, контрольные суммы результатов совпали до 3-го знака — выходные
пиксели не изменились):

| Семплирование | До | После |
| --- | ---: | ---: |
| `gradientColor`, 200 тыс. семплов | 25–38 мс | 12–20 мс (≈×2) |
| Шум Lab + прозрачность, 50 тыс. семплов | 91–102 мс | 63–94 мс (упирается в pow) |
| `gradientCss` ×48 семплов, 2 тыс. строк | 191–203 мс | 154–156 мс (−20%) |

`gradientColor` вызывается на каждый пиксель в коррекции «Карта градиента» и
заливке градиентом, поэтому ускорение ∝ площади изображения. Внешние обводки
больше не копируют полноразмерный канвас на каждый экземпляр обводки.

### Шаг 2+3 — code-splitting и мемоизация (коммиты 1df2ca3, befb412)

Первичная загрузка после оптимизации (тот же production build, та же методика):

| Чанк | raw, байт | gzip, байт |
| --- | ---: | ---: |
| index (приложение) | 410 595 | 127 315 |
| react | 222 302 | 68 719 |
| color-engine | 22 863 | 8 348 |
| CSS | 80 514 | 17 611 |
| **Итого первичной загрузки** | **736 274** | **221 993** |

Итог: −127 988 байт raw (−14,8%) и −37 612 байт gzip (−14,5%) на первичной
загрузке. 24 диалога вынесены в отдельные чанки (суммарно 138 892 raw /
58 308 gzip, крупнейший 18 КБ raw) и грузятся при первом открытии окна; рабочее
пространство, панели и холст синхронные. Предпросмотр градиента в диалогах
пересчитывает CSS-семплы только при реальном изменении определения градиента.

### Шаг 4 — регрессия

Локально на финальном коде оптимизации (befb412): Prettier и TypeScript чисты,
284 unit-теста (32 файла), 12 desktop security/IPC, 122 production browser e2e
и 35 независимых psd-tools интероп-кейсов — все зелёные, поведение и пиксели
не изменились. Windows CI (включая smoke исходного Electron и упакованного EXE)
проверяется на финальном коммите этой ветки.
